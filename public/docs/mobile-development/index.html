Expo, Supabase, Lucide ve RLS

Bu rehber, NewRssFeed için olası bir iOS ve Android uygulama yapısını ve güvenli veri erişim ilkelerini açıklar.

Mevcut durum: Bu depoda çalışan web tanıtım sitesi Vite ve TypeScript kullanıyor. Expo, React Navigation ve Supabase henüz projeye entegre edilmedi. Web sitesindeki Lucide ikonları CDN üzerinden yükleniyor; React Native paketi kullanılmıyor. Aşağıdaki kodlar planlama örneğidir, çalışan ürün özelliği veya uygulanmış veritabanı politikası değildir.

Önerilen sorumluluklar

  • Expo + React Native: iOS ve Android istemcisini geliştirmek ve derlemek için.
  • React Navigation: ekranlar, tab ve stack geçişleri için. Expo yeni projelerde Expo Router’ı öneriyor; React Navigation da geçerli bir seçenektir. Projede iki yönlendiriciyi birlikte kullanmak yerine biri seçilmelidir.
  • Supabase: PostgreSQL veritabanı, kullanıcı oturumu ve ihtiyaç olursa dosya depolama veya gerçek zamanlı güncellemeler için.
  • Lucide React Native: mobil arayüzde tutarlı SVG ikonları için.

Expo ile Supabase istemcisi

Expo’nun güncel Supabase kılavuzu @supabase/supabase-js ile expo-sqlite kullanarak yerel oturum saklamayı gösteriyor. Anahtarları uygulama ortam değişkenlerine koy; mobil pakete eklenen değerlerin gizli olmadığını varsay.

npx expo install @supabase/supabase-js expo-sqlite
import 'expo-sqlite/localStorage/install';
import { createClient } from '@supabase/supabase-js';

export const supabase = createClient(
  process.env.EXPO_PUBLIC_SUPABASE_URL!,
  process.env.EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY!,
  {
    auth: {
      storage: localStorage,
      autoRefreshToken: true,
      persistSession: true,
      detectSessionInUrl: false,
    },
  },
);

EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY istemci uygulamasında kullanılabilir; erişim sınırını RLS ve veritabanı izinleri belirler. service_role veya secret key’i uygulamaya, depoya ya da istemciye gönderilen ortamlara koyma.

React Navigation ve Expo Router

React Native’in çekirdeği bir yönlendirme sistemi içermez. React Navigation stack, tab ve drawer yapılarıyla kod üzerinden esnek ekran akışları kurar. Expo Router ise dosya tabanlı yönlendirme, derin bağlantı ve Expo araçlarıyla bütünleşme sağlar; Expo yeni projeler için bunu öneriyor. Karar verirken oturum açma akışı, derin bağlantılar ve web desteğini birlikte değerlendir.

Kimlik doğrulaması yalnızca ekranda hangi sayfaların gösterileceğini belirlemeli. Veriye kimin erişebileceğini yine Supabase RLS politikaları denetlemelidir; gizli ekran tek başına erişim kontrolü değildir.

Lucide ikonları

Web tanıtım sitesi şu anda Lucide’ın tarayıcı paketini kullanıyor. Expo/React Native tarafında Lucide’ın resmi paketi lucide-react-native’dir:

import { Bell } from 'lucide-react-native';

<Bell size={20} color="#6848e8" accessible accessibilityLabel="Bildirimler" />

Yalnızca kullanılan ikonları içe aktar ve etkileşimli ikonlara erişilebilir ad ver. Paket ve Expo uyumluluğu kuruluma başlamadan önce resmi Lucide ve Expo belgelerinden kontrol edilmelidir.

Supabase Row Level Security (RLS)

RLS, veritabanında hangi satırların okunup değiştirilebileceğini tanımlar. İstemci filtresine güvenmek yerine erişim kuralını tabloda uygula. Açık bir şemadaki tablolar için önce RLS’yi etkinleştir, gerekli SQL izinlerini ver ve her işlem için ayrı politika tanımla.

Aşağıdaki örnek, public.feed_items tablosunda UUID türünde owner_id alanı bulunduğunu varsayar. Bunu olduğu gibi çalıştırma; gerçek tablo ve paylaşım modeline göre uyarlayıp migration ve testlerle doğrula.

alter table public.feed_items enable row level security;

grant select, insert, update
on table public.feed_items
to authenticated;

create policy "Users read their own feed items"
on public.feed_items
for select
to authenticated
using ((select auth.uid()) = owner_id);

create policy "Users add their own feed items"
on public.feed_items
for insert
to authenticated
with check ((select auth.uid()) = owner_id);

create policy "Users update their own feed items"
on public.feed_items
for update
to authenticated
using ((select auth.uid()) = owner_id)
with check ((select auth.uid()) = owner_id);

create index if not exists feed_items_owner_id_idx
on public.feed_items (owner_id);
  • to authenticated rolü sınırlar; auth.uid() ise satırın mevcut kullanıcıya ait olduğunu kontrol eder. Sadece giriş yapmış olmak, satır sahipliğini kanıtlamaz.
  • INSERT için with check yeni satırın sahibini doğrular. UPDATE hem eski satırı using ile hem yeni satırı with check ile sınırlar.
  • UPDATE yapabilmek için uygun SELECT izni ve SELECT politikası da gerekir. İzinler RLS’den ayrı değerlendirilir.
  • Ortak akışlarda sahiplik tek başına yeterli değildir; üyelik ve paylaşım kuralları ayrıca tasarlanmalıdır. Karşılıklı tablo politikaları sonsuz özyineleme oluşturabilir.
  • RLS politikalarını anonim, sahip kullanıcı, başka bir kullanıcı ve beklenen paylaşım rolleri için veritabanı testleriyle doğrula. Erişim filtresi olan sütunlara uygun indeks ekle.
